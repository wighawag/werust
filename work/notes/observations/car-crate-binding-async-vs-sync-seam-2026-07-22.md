# CAR crate binding: the task's named `rs-car-ipfs`/`rs-car` are async-only, so the sync seam binds `rs-car-sync` + `ipld-dagpb` instead (2026-07-22)

Task `verifiable-ipfs-content-retrieval-seam-and-gateway-car-backend` names `rs-car-ipfs`/`rs-car` as the crates to bind for CAR parse + dag-pb/UnixFS decode, but both are async (`futures`/`async-std`) and `rs-car-ipfs`'s UnixFS decode is `pub(crate)` (not reusable). That conflicts with the task's own DECIDED constraint "over the existing sync `Fetcher` seam, no async runtime." Resolved to the task's clear INTENT (bind vetted crates, do not hand-roll CAR layout / dag-pb / crypto) by binding the sync siblings on the SAME `ipld-core`/`cid 0.11` lineage the repo already uses: `rs-car-sync` (sync CAR block reader + per-block CID verify) + `ipld-dagpb` (sync dag-pb decode) + a bound `quick-protobuf` decode of the UnixFS `Data` message. Full rationale + the rejected `unixfs-v1` (drags in a second `libipld`/`multihash 0.16` CID lineage) recorded in `docs/adr/0004`.
