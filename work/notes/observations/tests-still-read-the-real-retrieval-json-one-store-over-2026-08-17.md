# Tests still read the developer's real `retrieval.json`, one store over from the pins (2026-08-17)

Noticed while closing `pin-warning-reads-a-stale-cache-so-another-windows-bless-never-warns`, which made the PIN store an explicit production opt-in so no suite reads the developer's `pins.json`. Its sibling has the same read-side hole: `retrieval::active_gateway_endpoint()` calls `RetrievalSettings::load()` against the real settings directory, and every backend's `install_ipfs` calls it — so any test that builds a session (`CoreSession::new()` on both mobile crates, the desktop `install_ipfs` paths) reads whatever gateway the developer has picked locally. Nothing in the suites WRITES it, so this is the narrower hermeticity flavour again, not data loss; the directory-taking twin `active_gateway_endpoint_in` already exists for anything that wants isolation.
