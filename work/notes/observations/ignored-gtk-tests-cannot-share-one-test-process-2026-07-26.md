# The `--ignored` webview-renderer tests cannot all run in one test process (2026-07-26)

Running `cargo test -p webview-renderer -- --ignored --test-threads=1` fails: every one of these tests constructs a `WebViewRenderer` (which calls `gtk4::init()`), and after the first, GTK panics with "Attempted to initialize GTK from two different threads" (each `#[test]` runs on its own libtest thread, even at `--test-threads=1`), which then trips a SIGABRT on teardown. Pre-existing at `HEAD` (verified by stashing this task's change), so the documented "run on a desktop session with `cargo test -p webview-renderer -- --ignored`" instruction in several doc comments and spike READMEs only actually works when filtered to a SINGLE test. Not fixed here (out of scope for `fix-desktop-create-signal-crash-on-blank-links`); the fix is probably a `#[test]`-per-process harness or one `#[test]` that drives all the live cases in order.
