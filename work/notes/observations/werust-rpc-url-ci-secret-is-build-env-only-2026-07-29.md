# `WERUST_RPC_URL` CI secret pass-through cannot change a shipped artifact (runtime read, not compile-time bake)

Spotted while building task `configurable-rpc-endpoint-via-env` (2026-07-29).

The task prescribes two mechanisms: (1) `rpc_endpoint()` reads `WERUST_RPC_URL` via `std::env::var` at RUNTIME (session construction), and (2) `release.yml` exports `WERUST_RPC_URL` from `secrets.WERUST_RPC_URL` on every Rust-compiling leg "exactly as `WERUST_VERSION` is passed". The parity is only skin-deep: `WERUST_VERSION` reaches the shipped artifact because `build.rs` bakes it at COMPILE time (`env!`), while a job-env `WERUST_RPC_URL` is only present on the build machine. The installed desktop binary reads its user's runtime env (which CI cannot set), and on Android/iOS there is no user-settable env at all, so the CI secret currently has NO effect on any shipped artifact's endpoint. It is harmless forward-plumbing (and the shape test pins it), but if the intent is "releases built by CI resolve ENS via the private endpoint", a follow-up needs a compile-time bake (e.g. `option_env!` as a middle precedence between runtime env and `DEFAULT_RPC_ENDPOINT`) — noting that baking publishes the URL inside the public artifact, which may or may not be acceptable for a "private" endpoint.
