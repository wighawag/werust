# Task premise drift (minor): `ipfs.rs` has no `LocalGateway` loopback fixture

2026-07-23 (harden-loopback-test-servers-drain-request-body) — The task and both source flake notes list `LocalGateway` in `crates/werust-core/src/ipfs.rs` as a third copy of the single-`read()` loopback fixture to harden. On re-checking the code, `ipfs.rs` no longer has a `LocalGateway` (or any `TcpListener`/loopback HTTP server): its `#[cfg(test)] mod tests` is now pure `parse_ipfs_uri` / renderer-error tests with no request-body capture. So only two fixtures actually carry the flaky pattern today: `LocalRpcServer` (`ethereum.rs`) and `SequencedRpcServer` (`ens.rs`).

Decision: harden those two and share ONE helper between them, rather than invent an ipfs.rs fixture that does not exist. The shared reader `crate::loopback_test_server::read_request_body` lives crate-wide (in `lib.rs`), so any future `ipfs.rs` gateway fixture can reuse it in one line — the acceptance criterion "one hardened helper reused, not patched in only one" is satisfied at the crate level. Alternative considered: put the helper in `ethereum.rs` and `pub(crate)` re-export it — rejected because neither RPC module is the natural home for a gateway helper, and a crate-level test-support module reads as shared-by-design. This touches no other command/flag; it only narrows the fix surface from three fixtures to the two that exist.
